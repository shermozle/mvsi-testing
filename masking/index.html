How to read the network tab instead

  1. Open DevTools → Network, tick Preserve log, filter on amplitude.
  2. sr-client-cfg.amplitude.com/config (or, on this page, /sr-config/<api key>, a pinned copy of the project config from before any central rules existed): the remote-config fetch. Session Replay will not record if this fails when remote config is on; it fails closed.
  3. api2.amplitude.com/2/httpapi: analytics events as plain JSON. Autocapture events carry element IDs, classes, tags, hierarchy and visible text, never input values. Text matching email, credit card or social security patterns is masked by pattern (docs).
  4. api-sr.amplitude.com/sessions/v2/track: the replay payload. It is rrweb JSON (a full DOM snapshot, then diffs), compressed. The plugin uploads from a Web Worker, so in DevTools the request's initiator is the worker rather than the page. The panel on the right decodes it and lists every input value and text node it contains, so you can see asterisks where masking applied. Attribute values, image URLs and stylesheet URLs are sent as-is.

What the three levels mean, from the SDK's own rule

LevelInputs maskedPage text maskedWho it suits
LightOnly type=password, hidden, email, tel, and any input whose autocomplete starts with cc-. Everything else is sent in clear, including a TFN typed into a plain text box.None, unless you add maskSelector or .amp-mask.Low-sensitivity products. Not a KYB form.
Medium (default)All <input>, <select> and <textarea> values.None by default. Labels, headings and any PII rendered as text stay visible.Most products. For KYB, fine for the inputs, but review-step summaries that render the applicant's data as text are exposed.
ConservativeEvery input, select and textarea.Every text node on the page: labels, headings, paragraphs, links and review summaries, not only form fields. Images and attribute values are not text and are not masked.Financial services, healthcare, KYB. Combine with unmaskSelector for navigation labels so replays stay readable.
Masking is applied in the browser while the DOM snapshot is built. The asterisks you see in the payload are what Amplitude stores. There is no unmasked copy anywhere, which is also why rule changes cannot be applied retroactively (see recording-time privacy).

Source for the rule: the mask-level function in plugin-session-replay-browser 1.36.3, read directly from the minified bundle, and Manage privacy settings for Session Replay.
