4. Recording-time privacy

Where masking happens, what it cannot cover, and what changing a rule does to replays that already exist.

Masking happens in the browser, once, at capture time

Session Replay builds an rrweb snapshot of the DOM in the visitor's browser. While it serialises each node it applies the mask rules: a masked text node is written out as asterisks, a masked input's value is written out as asterisks, a blocked element is written out as an empty box of the same size. The unmasked value is never serialised, so there is no unmasked copy to transmit, store or leak. Amplitude's documentation puts it as: "Masking data prevents Amplitude from receiving it from your product." (docs)

Limits worth stating plainly

  • HTML attribute values are not masked at any level: value, placeholder, title, alt, aria-label, data-*. A form renderer that writes an applicant's name into a title attribute defeats masking. Block the element or stop writing data into attributes.
  • Text inside images, videos and canvases is not text and is not masked. Uploaded identity documents shown as image previews must be blocked (.amp-block or blockSelector).
  • URLs are recorded as-is unless ugcFilterRules rewrite them. An application ID in the path is visible in the replay list.
  • Light level is narrow: it masks only password, hidden, email and tel inputs plus card fields hinted with autocomplete="cc-". A tax file number in a plain text input is sent in clear at Light.
  • Autocapture is separate from replay masking. It never collects input values, and it pattern-masks element text that looks like an email, card or social security number, but the text of a review-step summary ("Director: Jane Citizen") is element text and would be captured on a click unless the element carries data-amp-mask.
  • Masking is per project, not per tenant form, unless each tenant is a project or the rules target a shared selector. The tenant-control page covers that.

Validating this with MVSI

  1. Set the project's level and overrides in Session Replay Settings.
  2. Capture a test session on a real tenant form with known test values (verify-capture procedure). Replays appear about five minutes after the session starts.
  3. Open the replay and confirm the test values are asterisks. Search the replay list for the application ID to check URL exposure.
  4. Change the level, capture a second session, and confirm the first replay is unchanged. That demonstrates both the prospective effect and the absence of retroactive change.
  5. Run a User Privacy API deletion for the test user and confirm both replays disappear.
